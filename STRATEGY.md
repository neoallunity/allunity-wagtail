# Стратегический план развития проекта AllUnity Wagtail

> Состояние на момент анализа (верифицировано): Wagtail 5.2.8 / Django 4.2.30, проект
> собирается и рендерит 27 страниц, миграция воспроизводима, CI зелёный, security-харденинг
> прод-настроек выполнен. Docker-сборка в текущем sandbox заблокирована (нет прав на сокет).
> Статическое зеркало на PythonAnywhere (dominicusin.pythonanywhere.com) живо, но это НЕ Wagtail.
> live allunity.ru жив.

## 0. Текущая позиция (SWOT)

**Сильные стороны**
- Рабочий, воспроизводимый Wagtail-проект с реальным контентом (27 стр., Кодекс из 8 статей,
  Новости×4, Проекты×5, Словарь/Школа/История заполнены).
- Идемпотентная миграция контента (`migrate_data`) — единый источник правды при переносе.
- CI: check + makemigrations --check + тесты + воспроизводимость миграции (настоящий раннер).
- Готовый Docker-стек (Postgres/Redis/Nginx) + prod-настройки (HSTS, secure-cookies, SECRET_KEY из env).
- Поиск, RSS, sitemap, robots, breadcrumbs, a11y-основы, favicon — уже есть.

**Слабые стороны**
- Нет живого инстанса: Wagtail нигде не опубликован, статическое зеркало на PA — это другой код.
- Тестовое покрытие узкое: 12 тестов только в `core`, модели `discussions`/`news`/`projects`/
  `feeds`/`SearchPage` покрыты косвенно или не покрыты.
- Часть контента — осмысленные заглушки (Словарь/Школа/История/Эмблема), т.к. на live они пусты.
- Развёртывание не проверено реальным `docker compose up` (sandbox блокирует сокет).
- `wagtail.contrib.modeladmin` deprecated в Wagtail 6 — при апгрейде сломается.

**Возможности**
- Поднять живой инстанс (PythonAnywhere Web App или Docker-хост) → сайт реально работает для сообщества.
- Расширить контент: Discussions (реальные треды), медиа (интеграция с GitHub Pages, как в зеркале).
- Превратить мигратор в постоянный импортёр (cron) для синхронизации со старым сайтом.
- SEO/аналитика, мультиязычность (RU/EN), тёмная тема.

**Угрозы**
- `allunity.ru` может измениться/исчезнуть → мигратор привязан к текущей структуре SHTML.
- Wagtail 5.2 → 6.x требует миграции (modeladmin, возможно StreamField API).
- Без живого инстанса проект — «демо», а не продукт.

## 1. Стратегические цели (приоритеты)

1. **ДОСТАВКА (Must-have)**: поднять живой, публичный инстанс Wagtail — иначе ценность проекта
   не реализована. Выбор хостинга ниже.
2. **НАДЁЖНОСТЬ (Must-have)**: расширить тесты + добавить e2e smoke (все разделы 200),
   защитить от регрессий при апгрейде Wagtail.
3. **КОНТЕНТ (Should-have)**: наполнить Discussions реальными тредами; связать медиа
   (GitHub Pages) как в исходном зеркале.
4. **ЭВОЛЮЦИЯ (Should-have)**: запланировать апгрейд до Wagtail 6 (убрать modeladmin),
   добавить удобство (тёмная тема, мультиязычность, аналитика).
5. **ИНТЕГРАЦИЯ (Could-have)**: сделать мигратор периодическим импортёром; связать
   статическое зеркало и Wagtail перекрёстными ссылками.

## 2. Дорожная карта (этапы)

### Этап A — Доставка живого инстанса  [БЛОКЕР текущей ценности]
- Вариант 1 (рекомендую, т.к. уже есть аккаунт): **PythonAnywhere Web App** — загрузить
  проект, Postgres-аддон (или SQLite для старта), `SECRET_KEY`/`ALLOWED_HOSTS` из переменных
  веб-приложения, WhiteNoise для статики (или PA static files). Проверить `GET /` + `/admin/`.
- Вариант 2: Docker-хост (VPS) — `docker compose up`, nginx+certbot. Требует Docker-доступа
  (в sandbox заблокирован, выполнить на хосте).
- Критерий: публичный URL отвечает 200 по всем разделам + `/admin/` доступен авторизованному редактору.

### Этап B — Расширение тестов и e2e  [защита от регрессий]
- Тесты на `DiscussionPage` (создание/рендер), `ProjectPage` seed, `NewsFeed` (RSS содержит items),
  `SearchPage` (реальный запрос возвращает результат), `EmblemPage`/`DictionaryPage`/`SchoolPage`/
  `HistoryPage` рендер.
- Playwright/Wagtail `TestCase` smoke: зайти по всем slug'ам → 200.
- Добавить шаг CI «smoke всех страниц 200» после миграции.
- Цель: покрытие моделей ≥ 80%.

### Этап C — Наполнение Discussions + медиа  [контент]
- Спарсить реальные дискуссии с live (если есть публичные) или создать 3–5 демо-тредов.
- Подключить тяжёлые медиа (Дискуссии/Книги/Журналы) с GitHub Pages, как в исходном зеркале —
  внешние ссылки, чтобы не раздувать БД/квоту.

### Этап D — Апгрейд Wagtail 5.2 → 6.x  [эволюция, подготовка]
- Убрать `wagtail.contrib.modeladmin` (заменить на `wagtail.snippets` / `wagtail-modeladmin` пакет).
- Проверить StreamField/Image API изменения.
- Обновить CI на Wagtail 6, прогнать тесты.

### Этап E — Удобство и продвижение  [could-have]
- Тёмная тема (toggle + localStorage), мультиязычность RU/EN (Wagtail localization),
  базовая аналитика (privacy-friendly, self-hosted), OG-картинки для шаринга.

### Этап F — Интеграция зеркал  [could-have]
- На статическом зеркале PA добавить баннер-переход на живой Wagtail-инстанс.
- Сделать `migrate_data` периодическим (cron/management-command) для синхронизации со старым сайтом.

## 3. Риски и решения
- **Docker заблокирован в sandbox** → доставку (Этап A) делать на хостинге с доступом;
  верифицировать через `check --deploy` + реальный HTTP-доступ инстанса.
- **Wagtail 6 ломает modeladmin** → Этап D выполнить до прод-нагрузки, иначе техдолг.
- **allunity.ru меняет структуру** → мигратор уже устойчив к отсутствию страниц (fetch возвращает ""),
  но парсеры `parse_articles`/`parse_terms` привязаны к заголовкам — добавить тесты на парсеры.

## 4. Критерии успеха (Definition of Done)
- [ ] Живой публичный инстанс Wagtail отвечает 200 по всем разделам + `/admin/`.
- [ ] Тестовое покрытие моделей ≥ 80%, CI включает e2e-smoke всех страниц.
- [ ] Discussions наполнены, медиа связаны с GitHub Pages.
- [ ] Wagtail обновлён до 6.x без modeladmin, тесты зелёные.
- [ ] Документация (README + STRATEGY) отражает реальность.
